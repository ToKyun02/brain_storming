# 4개 핵심 화면

## 1. 방 생성 / 초대

**라우트:** `/` (대시보드), `/rooms/new`

### 기능
- 구글 OAuth 소셜 로그인
- 방 생성 (제목 + 브레인스토밍 주제 입력)
- 초대 링크 자동 발급 + 클립보드 복사
- 초대 링크 접근 시 로그인 후 자동 입장

### 플로우

```
[구글 로그인] → [대시보드] → [방 생성] → [초대 링크 발급]
                                              ↓
                                   [초대받은 멤버] → [링크 클릭] → [자동 입장]
```

### 핵심 API
- `GET /auth/google` — 구글 OAuth 리다이렉트
- `POST /rooms` — 방 생성
- `GET /rooms/join/:token` — 초대 링크 입장

## 2. 메인 브레인스토밍 보드 (핵심)

**라우트:** `/rooms/[id]`

### 기능

| 기능 | 설명 |
|---|---|
| 포스트잇 카드 | 카드 추가·삭제, 멤버별 색상 고정 |
| 실시간 동기화 | WebSocket으로 모든 멤버에게 즉시 반영 |
| 투표 | 카드에 투표, 득표순 실시간 정렬 |
| 멤버 아바타 | 현재 접속 중인 멤버 아바타 표시 |
| AI 분석 요청 | 방장이 버튼 클릭 → AI 패널에 스트리밍 시작 |

### 레이아웃

```
┌────────────────────────────────────┬──────────────────┐
│           브레인스토밍 보드         │    AI 패널       │
│                                    │                  │
│  [멤버 아바타 목록]                 │  [AI 단계 뱃지]  │
│                                    │  정리자 → 추천자  │
│  ┌──────┐ ┌──────┐ ┌──────┐       │  → 반박자        │
│  │ 카드 │ │ 카드 │ │ 카드 │       │                  │
│  └──────┘ └──────┘ └──────┘       │  [AI 응답 스트림] │
│                                    │  타이핑 효과...   │
│  [+ 카드 추가]    [AI 분석 요청]   │                  │
└────────────────────────────────────┴──────────────────┘
```

### 관련 이벤트
- `card.add` / `card.delete` — 카드 실시간 동기화
- `vote.update` — 투표 수 실시간 반영
- `member.join` / `member.leave` — 아바타 표시
- `ai.stream` / `ai.done` — AI 응답 스트리밍

## 3. AI 패널

**위치:** 브레인스토밍 보드 우측 패널

### AI 역할 단계

| 단계 | 뱃지 | 역할 | 언제 |
|---|---|---|---|
| 1단계 | 🔵 정리자 | 의견 요약 + pros/cons | 초반 아이디어 발산 후 |
| 2단계 | 🟡 추천자 | 적극 추천 + 근거 제시 | 의견이 좁혀질 때 |
| 3단계 | 🔴 반박자 | "이건 생각해봤어요?" | 결정 직전 검증 |

### 기능
- 방장이 단계 수동 전환 → `PATCH /rooms/:id/ai/stage`
- AI 응답 **스트리밍** (타이핑 효과, `ai.stream` 이벤트)
- 세션 내 AI 히스토리 스크롤 (`GET /rooms/:id/ai/history`)

### AI 프롬프트 구조 (예시)

```
[정리자 단계]
다음은 팀의 브레인스토밍 카드입니다:
- {카드 내용들}

의견을 항목별로 요약하고, pros/cons를 정리해주세요.
```

## 4. 결정 히스토리

**라우트:** `/decisions`, `/decisions/[id]`

### 기능
- 종료된 방 목록 조회 (`GET /decisions`)
- 세션 요약: 주제, 참여자, 상위 득표 카드, AI 마지막 응답
- JSON / 마크다운 Export (S3 저장 URL로 다운로드)
- **읽기 전용** — 수정 불가

### 세션 요약 구조

```
📋 결정 히스토리: DB 기술 선택

주제: PostgreSQL vs MongoDB 어떤 게 맞을까요?
참여자: 홍길동, 김철수, 이영희 (3명)
진행일: 2024-01-15

상위 카드 (득표순):
  1. PostgreSQL이 트랜잭션 지원이 강력해서 좋을 것 같아요. (👍 5)
  2. MongoDB는 스키마 유연성이 장점이지만... (👍 3)

AI 최종 반박 단계 요약:
  "트랜잭션 일관성이 중요한 서비스라면 PostgreSQL이 맞지만,
   향후 스키마 변경 빈도를 고려해보셨나요?"

최종 결정:
  PostgreSQL을 사용하기로 결정했습니다.
```
